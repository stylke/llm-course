# Gensim与fastText源码阅读笔记

我先按课件第143—149、154—169页梳理CBOW、Skip-gram和负采样，再看Gensim的训练入口与底层循环。这份笔记记录Gensim 4.3.3和fastText 0.9.3中与本次实验相关的函数。源码行号会随版本变化，下面主要用函数名定位。

## 1. FastText词向量与监督分类

Gensim的 `gensim.models.FastText` 与 `Word2Vec` 一样，用词及上下文训练静态词向量。我的主实验将这些向量固定，聚合成文章向量，再由scikit-learn逻辑回归学习类别。

Joulin等的 *Bag of Tricks for Efficient Text Classification* 把文本中的词和词n-gram聚合后预测标签，输入表示与分类器一起训练。我用官方 `fasttext.train_supervised` 另跑一组实验，比较这种联合训练方式的结果。

对应论文：

- Mikolov等，*Efficient Estimation of Word Representations in Vector Space*，2013，arXiv:1301.3781。
- Mikolov等，*Distributed Representations of Words and Phrases and their Compositionality*，2013，arXiv:1310.4546。
- Bojanowski等，*Enriching Word Vectors with Subword Information*，2016预印本、2017 TACL，arXiv:1607.04606。
- Joulin等，*Bag of Tricks for Efficient Text Classification*，2016预印本、2017 EACL，arXiv:1607.01759。

## 2. Gensim的训练调用链

`Word2Vec.__init__` / `FastText.__init__` 接收语料后，先 `build_vocab`，再 `train`。词频统计、`min_count`筛选、负采样表和参数初始化在Python层完成；核心更新在Cython中完成。`FastText._do_train_job` 调到 `fasttext_inner.train_batch_any`，后者初始化配置、把词映射到索引，再进入 `fasttext_train_any`。

`fasttext_inner.pyx` 中几个关键函数：

| 函数 | 我读到的作用 |
| --- | --- |
| `populate_ft_config` | 跳过不在训练词表中的词，对高频词下采样，预取每个词的子词桶索引 |
| `fasttext_train_any` | 逐句划定上下文边界，按 `sg`、`negative`、`hs` 选择训练分支 |
| `fasttext_fast_sentence_sg_neg` | 合成中心词表示，更新一个正例和至多K个负例 |
| `fasttext_fast_sentence_cbow_neg` | 聚合窗口内的上下文表示，预测中心词 |
| `compute_ngrams_bytes` | 按UTF-8字符边界枚举字符n-gram，包含词首、词尾标记 |
| `ft_hash_bytes` | FNV-1a字节哈希 |

我原先把 `window=5` 理解为每次固定看两侧5个词。读代码后发现，默认 `shrink_windows=True` 会为位置随机减小窗口半径，5是最大值。上下文窗口始终位于同一条新闻标题或同一个正文句子内。

`populate_ft_config` 会过滤低于 `min_count` 的词，这些词在训练时被跳过。推理时，FastText可以利用其他保留词中学到的子词表示，为OOV组合向量。

## 3. 负采样与论文公式

对中心词表示 \(h_w\)、正上下文输出向量 \(u_c\) 和K个负例，可写成要最大化的目标：

$$
\log \sigma(u_c^\top h_w)
+\sum_{i=1}^{K}\log \sigma(-u_{n_i}^\top h_w).
$$

底层循环先令正例 `label=1`，负例 `label=0`，点积查sigmoid表得到 \(p\)，再计算 `g=(label-p)*alpha`。随后以BLAS的 `saxpy` 更新输出向量，并把累积误差加回输入词向量及子词向量。代码直接访问参数矩阵中对应的行。

具体实现还有以下细节：

1. 负样本抽到当前正上下文时会跳过，实际更新的负例数至多为K个。
2. sigmoid使用查表近似，超出限定范围的点积会跳过该分支。
3. `Word2Vec.make_cum_table` 用 `count**ns_exponent` 建立累计分布。本次设置0.75，Bojanowski等子词论文的实验采用词频平方根采样，即0.5。
4. Gensim保留 `vectors_vocab` 和输出矩阵 `syn1neg` 两套角色不同的向量。`model.wv[word]` 返回完整词与子词组合后的输入表示，输出矩阵单独保存。

## 4. 子词表示与中文参数

子词论文把词表示为完整词与字符n-gram表示的和。比如 `min_n=1,max_n=3` 时，“足球”有：

```text
<足  <足球  足  足球  足球>  球  球>
```

枚举子词时会排除裸 `<`、`>`。`compute_ngrams_bytes` 遍历UTF-8编码，跳过续字节，按完整字符扩展，因此一个汉字对应一个字符单位。

Gensim中有几处向量缩放：`fasttext_fast_sentence_sg_neg` 先复制完整词向量，再加上子词向量；存在子词时，用 `subwords_len` 做缩放。取最终词向量的 `FastTextKeyedVectors.adjust_vectors` 把“完整词 + 所有子词”的和除以 `len(ngram_buckets)+1`。OOV的 `get_vector` 只平均其子词桶向量。训练循环和最终取向量函数使用的分母有所不同。

一个词向量乘以正比例常数后，余弦相似度保持不变。文章向量由多个词向量平均得到，各词的缩放会改变它们在聚合中的相对权重。

中文词往往较短，所以我比较了1—3字符与3—6字符两组范围。加上 `<`、`>` 后，“足球”在3—6范围内可以产生 `<足球`、`足球>` 和 `<足球>`。1—3范围增加了单字共享，也可能把“足球”“眼球”等包含同字但主题不同的词拉近。

`ft_ngram_hashes` 将字节n-gram通过FNV-1a映射到固定 `bucket`。不同字符串可能共享一个桶。本次桶数较小，节省了内存，也增加了哈希冲突，冲突数量由 `analyze.py` 统计。OOV中的新子词也会映射到这些桶，取到的向量可能来自初始化值或其他子词的训练更新。

## 5. 周边代码和参数

`word2vec.py` 的 `prepare_vocab` 建立词表，并计算高频词下采样阈值 `sample_int`。预处理保留“的、是”等停用词，词向量训练时通过下采样处理，文章聚合时通过IDF调整权重。

`_job_producer` 把语料拆成训练批次，并随进度降低学习率。多线程队列可以提高速度，也会改变更新顺序。本次使用 `workers=1`、固定种子，并用SHA256构造稳定的初始化哈希。库版本、编译器和数值后端的差异仍可能带来数值变化。

`min_count`控制长尾词是否有独立完整词参数；`vector_size`影响表达容量与矩阵大小；`epochs`决定遍历次数；`negative`控制每个正例的对比更新成本；`sample`影响高频词保留概率；`bucket`控制子词表大小。

保存时，Gensim模型包含词表、训练状态和矩阵；`wv`主要用于查向量。本次用 `model.save` 保留模型，并用 `load` 检查文章分类输出一致。文章向量函数对Word2Vec的OOV词作跳过处理，对FastText的OOV词作子词组合，最后进行L2归一化。Word2Vec遇到全部词都为OOV的文章时返回零向量。

## 6. 官方监督式fastText

我从PyPI下载了对应实际安装版本的 `fasttext-0.9.3.tar.gz`，查看以下位置：

| 源码位置 | 与论文的对应 |
| --- | --- |
| `src/dictionary.cc`，`getLine` | 识别 `__label__`，按空白读词，不执行中文分词 |
| `src/dictionary.cc`，`addWordNgrams` | 滚动哈希连续词n-gram，加入输入特征 |
| `src/model.cc`，`computeHidden` | 累加输入特征行并除以特征数，得到文本表示 |
| `src/model.cc`，`update` | 计算损失，并更新输入表示与输出分类参数 |
| `src/fasttext.cc`，`supervised` | 从标签进入监督训练分支 |

`wordNgrams=2` 指“足球 比赛”这样的连续词bigram。Gensim的 `min_n,max_n` 控制“足”“球”等词内部的字符子词。监督式入口默认 `minn=maxn=0`；本次也显式关闭字符子词，单独观察词bigram的影响。

论文用层次softmax加速大类别分类。本实验只有2—4类，使用普通softmax，设置 `loss="softmax"`。主实验逻辑回归使用类别均衡权重，官方fastText使用原始类别分布，两组在类别权重和训练方式上都有差别。

## 7. 一次环境排查

开始使用Python 3.13和NumPy 2时，矩阵乘法出现浮点警告；最小数值对照显示结果有限且与直接求和一致。后来改到Python 3.10、NumPy 1.26.4、SciPy 1.13.1，消除了这一警告，但Gensim 4.4.0仍偶尔打印 `Exception ignored ... our_dot_float`。

查看本机wheel自带的 `word2vec_inner.c`，发现它把点积返回的 `-1.0` 当作异常哨兵，进入返回0的分支。Gensim 4.3.3的同处代码直接返回点积。因此最终切换到4.3.3，并重新训练全部模型、生成预测和补充检查。最终日志未屏蔽警告，第三方库源码保持原样。

这次排查后，我记录了软件版本和运行日志，并检查了模型数值、保存后加载的预测结果，以及从逐篇预测复算出的指标。这些检查都通过了。
